# Tags

**Tags** are labels you attach to **decks** and **facts** to organize and filter your material. They belong to **your account**, not to a single deck — you create a tag once and can use it on many decks and many facts.

Tags are optional. Decks and facts work fine without them; tags help when you want to group content (for example `verb`, `JLPT N3`, or `hard`) or study a subset of cards in a deck.

## How tags relate to decks and facts

| Where    | What tags do                                                                             |
| -------- | ---------------------------------------------------------------------------------------- |
| **Deck** | Mark the whole deck (e.g. `Japanese`, `exam-prep`). Up to **100** tags per deck.         |
| **Fact** | Mark individual items inside a deck (e.g. `noun`, `food`). A fact can have several tags. |

**Fields** define columns on a deck; **tags** are separate metadata for filtering and organization. Facts still store **entries** only — tags are linked alongside the fact, not inside entry text.

The same tag name can appear on multiple decks and multiple facts. Deleting a tag removes it everywhere it was attached.

Across one deck, distinct fact-level tags are capped (union across all facts in that deck, up to **200**).

## Creating and managing tags

You can add tags when you create or edit a deck or fact (pick existing tags or create by name), and you can manage your tag library from the app (create, rename, delete).

Each tag has a **name** and an optional **description**. Names must be unique for your account after normalization (trimmed, spaces collapsed, compared case-insensitively). Allowed characters include **Unicode** letters and numbers, spaces, hyphen (`-`), and apostrophe (`'`).

**Limits:**

- Up to **1000** tags per user
- Up to **100** tags on one deck
- Up to **200** distinct fact tags per deck (union across facts)

## Tagging facts and decks

When you add or edit facts, you can attach optional **tags** — for example one row as `verb` and another as `food`. Different facts can have different tags, or none.

You can also tag a deck when you create it or later — useful for browsing your library, not for changing how individual cards are laid out.

## Studying with tags

During review, you can focus on cards whose facts have a given tag **in that deck**. Tags do not change a card’s front/back layout — they only narrow **which** cards are eligible for study.

## Imported decks

On decks you **import**, **tags are yours** for study filters and organization. Tag and content suggestions on imports can also be sent to the author as **contributions**; that is separate from your local labels. Shared fact bodies still follow the published snapshot until you sync an update. See [Import an existing deck](/guide/get-started/import-an-existing-deck).

## Summary

Tags are per-user labels on **decks** and **facts** for organization and filtered study. They complement deck **fields** and fact **entries**, which hold the actual learning material.
